## 一、文档概述

### 1.1 项目定位

Believe 是一套从零构建的通用型微服务架构，旨在提供生产级的基础设施能力、标准化的开发规范和完整的CI/CD交付流程。

### 1.2 核心目标

- 构建可复用的基础框架Starter集合
- 实现服务注册发现、配置管理、网关路由、限流熔断、认证授权等核心能力
- 建立完整的容器化部署和CI/CD流水线
- 深度掌握SPI、Spring Boot自动配置等底层机制

### 1.3 技术原则


| 原则         | 说明                                    |
| ------------ | --------------------------------------- |
| 约定优于配置 | 提供合理的默认值，降低使用门槛          |
| 开闭原则     | 通过SPI和条件注解支持扩展，核心逻辑封闭 |
| 可观测性优先 | 所有组件必须暴露日志、指标、链路信息    |
| 云原生友好   | 支持容器化部署和K8s编排                 |

## 四、核心组件设计

### 4.1 believe-common-core

**职责**：提供最基础的工具能力和公共契约，是整个框架的唯一底层依赖。


| 包路径                              | 功能         | 核心类                                             |
| ----------------------------------- | ------------ | -------------------------------------------------- |
| `com.believe.common.core.result`    | 统一返回结果 | `Resultt`、`PageResultt`                           |
| `com.believe.common.core.constants` | 系统常量     | `ServiceConstants`、`HeaderConstants`、`ErrorCode` |
| `com.believe.common.core.utils`     | 通用工具类   | `JsonUtil`（Jackson 3）、`DateUtil`、`IdUtil`      |
| `com.believe.common.core.exception` | 基础异常定义 | `BelieveException`、`BizException`                 |
| `com.believe.common.core.context`   | 上下文持有者 | `AuthContext`、`RequestContext`                    |

**核心契约定义**：

- 统一响应格式：`{ code, message, data, timestamp }`
- 错误码规范：1xxx参数错误，2xxx业务错误，3xxx系统错误，4xxx权限错误，5xxx服务调用错误
- 透传Header约定：`X-Trace-Id`、`X-User-Id`、`X-Username`、`X-Authorities`

**依赖引入**：


| 依赖                  | GroupId                      | 说明                       |
| --------------------- | ---------------------------- | -------------------------- |
| `jackson-databind`    | `tools.jackson.core`         | Jackson 3 核心             |
| `jackson-annotations` | `com.fasterxml.jackson.core` | Jackson 注解（包名未迁移） |
| `lombok`              | `org.projectlombok`          | 简化代码（provided）       |

#### 4.1.1 Result / PageResult

- 统一使用 `Resultt` 和 `PageResultt` 作为返回体
- 基于 Lombok `@Data` + `@Accessors(chain=true)`，支持链式调用
- `Result` 提供静态工厂方法：`ok()`、`ok(data)`、`error(code, message)`
- `Result` 提供快捷判断：`isSuccess()`、`isError()`
- `PageResult` 提供：`of(total, records)`、`empty()`、`hasData()`、`getTotalPages()`

#### 4.1.2 AuthContext（认证上下文）

- **设计模式**：实例式 ThreadLocal，通过 `AuthContext.get()` 获取当前线程实例
- **链式设置**：`setUserId()`、`setUsername()`、`setToken()`、`setAuthorities()`
- **值获取**：`getUserId()`、`getUsername()`、`getToken()`、`getAuthorities()`
- **便捷判断**：`isLogin()` — 判断当前请求是否已认证
- **调试支持**：`getAll()` — 返回所有上下文数据的快照

#### 4.1.3 RequestContext（请求上下文）

- **设计模式**：实例式 ThreadLocal，通过 `RequestContext.get()` 获取当前线程实例
- **链式设置**：`setTraceId()`、`setClientIp()`、`setUserAgent()`
- **值获取**：`getTraceId()`、`getClientIp()`、`getUserAgent()`
- **便捷判断**：`hasTraceId()` — 判断是否已设置链路追踪ID

#### 4.1.4 异常体系

- `BelieveException`：基础异常类，使用 Lombok `@Getter`，含 `code` + `message`
- `BizException`：业务异常，继承 `BelieveException`，默认错误码 `BIZ_GENERAL`
- 构造函数支持传入 `Throwable cause` 以保留异常链

#### 4.1.5 JsonUtil（Jackson 3 实现）

- 核心包名：`tools.jackson`（非 `com.fasterxml.jackson`）
- 构建方式：`JsonMapper.builder()` 替代 `new ObjectMapper()`
- 日期配置：`DateTimeFeature.WRITE_DATES_AS_TIMESTAMPS` 替代旧 API
- 特性：美化输出、忽略未知属性
- 注解包名 `com.fasterxml.jackson.annotation` 保持不变，`@JsonProperty`、`@JsonIgnore`、`@JsonFormat` 正常使用
- 公开 `mapper()` 方法，供下游模块（如 Redis 序列化器）复用单例 JsonMapper

#### 4.1.6 DateUtil / IdUtil

- `DateUtil`：基于 `java.time` 的日期工具，支持格式化、解析、`startOfDay`/`endOfDay` 等
- `IdUtil`：提供 `uuid()`（无横线）、`uuidWithDash()`（带横线）、`simpleId()`（自增，仅开发测试用）

### 4.2 believe-common-redis

**职责**：封装Redis操作，提供开箱即用的缓存能力

**自动配置触发条件**：`RedisTemplate` 存在于classpath

**暴露的Bean**：


| Bean名称               | 类型                   | 说明                                         |
| ---------------------- | ---------------------- | -------------------------------------------- |
| `redisTemplate`        | `RedisTemplatestring,` | Jackson 3`JacksonJsonRedisSerializer` 序列化 |
| `redisDistributedLock` | `RedisDistributedLock` | 基于 SET NX EX + Lua 脚本的分布式锁          |
| `cacheManager`         | `CacheManager`         | Spring Cache 集成，默认TTL 1小时             |

**分布式锁设计**：

- 锁令牌由 ThreadLocal 管理，确保 tryLock/unlock 的 requestId 在同一线程内匹配
- `unlock` 通过 Lua 脚本原子校验持有者，避免误删
- `execute` 模板方法封装 tryLock → action → unlock 完整生命周期

**Jackson 3 适配**：序列化器使用 Spring Data Redis 4.0 的 `JacksonJsonRedisSerializer`，废弃旧的 `Jackson2JsonRedisSerializer`

### 4.3 believe-common-data

**职责**：数据持久化增强，统一管理数据源配置、动态路由、自动填充、分页等能力。

**自动配置触发条件**：`DataSource` 和 `MybatisPlusAutoConfiguration` 存在

#### 4.3.1 四种数据源模式

通过配置属性按需激活，互斥生效：


| 模式         | 激活条件                                     | 说明                            |
| ------------ | -------------------------------------------- | ------------------------------- |
| **单数据源** | 默认（其他模式均未开启时）                   | `SingleDataSourceConfig`        |
| **读写分离** | `believe.data.read-write-split.enabled=true` | 一主一从，读走从库、写走主库    |
| **多数据源** | `believe.data.multi-datasource.enabled=true` | 支持 master / slave / report 等 |
| **分库分表** | `believe.data.sharding.enabled=true`         | ShardingSphere 接管，YAML 驱动  |

**架构设计**：

- 所有模式继承 `BaseDataSourceConfig` 抽象类
- `BaseDataSourceConfig.createDataSource()` 统一入口，根据 `isDynamicRouting()` 决定是否启用动态路由
- 动态路由基于 `AbstractRoutingDataSource`（`DynamicDataSource`），配合 `LazyConnectionDataSourceProxy` 延迟获取连接
- `DataAutoConfiguration` 通过 `@Import` 统一注册所有模式配置，由各 `@ConditionalOnProperty` 控制激活

#### 4.3.2 @DataSource 注解与 AOP 动态切换

- `@DataSource("slave")` 注解用于方法或类级别，声明式切换数据源
- `DataSourceAspect`（AspectJ 切面，Order=1）在方法执行前设置、执行后清理
- `DynamicDataSourceContextHolder`（ThreadLocal）存储当前线程的数据源标识

#### 4.3.3 MyBatis-Plus 配置

**MybatisPlusConfig** 提供：


| 组件                     | 说明                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `MybatisPlusInterceptor` | 注册分页插件（`PaginationInnerInterceptor`）和乐观锁插件（`OptimisticLockerInnerInterceptor`） |
| `MetaObjectHandler`      | 自动填充处理器，可通过`believe.data.mybatis-plus.auto-fill=false` 关闭                         |

**Mapper 扫描**：自动扫描 `com.believe.**.mapper` 路径。

#### 4.3.4 自动填充规范

`MybatisMetaObjectHandler` 实现：

- `createTime`：插入时填充 `LocalDateTime.now()`
- `updateTime`：插入和更新时填充 `LocalDateTime.now()`
- `createBy`：从 `AuthContext.get().getUserId()` 获取，未登录时默认 `"system"`
- `updateBy`：从 `AuthContext.get().getUserId()` 获取，未登录时默认 `"system"`
- `deleted`：插入时默认 `0`

#### 4.3.5 BaseEntity（基础实体）

抽象基类，所有实体继承后自动获得：


| 字段         | 注解                                        | 说明                             |
| ------------ | ------------------------------------------- | -------------------------------- |
| `id`         | `@TableId(type=IdType.AUTO)`                | 自增主键                         |
| `createTime` | `@TableField(fill=FieldFill.INSERT)`        | 创建时间（自动填充）             |
| `updateTime` | `@TableField(fill=FieldFill.INSERT_UPDATE)` | 更新时间（自动填充）             |
| `createBy`   | `@TableField(fill=FieldFill.INSERT)`        | 创建人（自动填充）               |
| `updateBy`   | `@TableField(fill=FieldFill.INSERT_UPDATE)` | 更新人（自动填充）               |
| `deleted`    | `@TableLogic`                               | 逻辑删除标记（0=正常，1=已删除） |

#### 4.3.6 CustomSqlInjector

继承 `DefaultSqlInjector`，注入 `InsertBatchSomeColumn` 批量插入方法。

### 4.5 believe-common-exception

**职责**：全局异常统一处理，错误码到HTTP状态码的标准化映射

**自动配置**：`@RestControllerAdvice` + `@AutoConfiguration` + `@Import`，Spring Boot 4.0 自动配置机制注册

**异常处理能力**：


| 异常类型                                               | HTTP状态码       | 错误码             |
| ------------------------------------------------------ | ---------------- | ------------------ |
| `BelieveException`                                     | 按错误码分类映射 | 取决于业务错误码   |
| `MethodArgumentNotValidException`                      | 400              | PARAM_INVALID      |
| `MissingServletRequestParameterException`              | 400              | PARAM_MISSING      |
| `HttpMessageNotReadableException`                      | 400              | PARAM_INVALID      |
| `NoHandlerFoundException` / `NoResourceFoundException` | 404              | BIZ_DATA_NOT_FOUND |
| `HttpRequestMethodNotSupportedException`               | 405              | PARAM_INVALID      |
| `Exception`（兜底）                                    | 500              | SYS_GENERAL        |

**错误码→HTTP状态码映射规则**：

- 1xxx（参数）、2xxx（业务）→ 400
- 3xxx（系统）→ 500
- 4xxx（权限）：4001 → 401，其余 → 403
- 5xxx（RPC）→ 502
- 其余 → 500

### 4.6 believe-common-log

**职责**：提供日志链路追踪与AOP方法日志能力

**自动配置导入**：`TraceIdFilter`、`LogAspect`

**核心组件**：


| 组件            | 类型                   | 说明                                                                |
| --------------- | ---------------------- | ------------------------------------------------------------------- |
| `@Log` 注解     | 方法级注解             | 自定义描述、可控制打印参数/返回值                                   |
| `TraceIdFilter` | `OncePerRequestFilter` | 从请求头`X-Trace-Id` 提取或生成 TraceId，写入 MDC 和 RequestContext |
| `LogAspect`     | AOP 切面               | `@Around` 拦截 `@Log` 方法，记录入参、耗时、异常                    |

**TraceId 传播链路**：

1. 请求到达 → `TraceIdFilter` 从 `X-Trace-Id` 头提取或 `IdUtil.uuid()` 生成
2. 写入 MDC（`traceId` 键）→ 日志框架自动附加到每行日志
3. 写入 `RequestContext.get().setTraceId()` → 可通过上下文获取
4. 请求结束 → Filter finally 块清理 MDC 和 RequestContext

**依赖引入**：`spring-boot-starter-web`（含 spring-web、自动配置）+ `aspectjweaver` + `lombok`

### 4.12 believe-auth（认证中心）

**职责**：用户认证、Token颁发、权限管理

**核心接口**：

### 4.14 believe-common-spi-extension

**职责**：为 `believe-common-spi` 定义的三个扩展点提供生产级默认实现，实现接口与实现的分离。

**自动配置触发条件**：依赖于 `believe-common-spi` 模块，通过 `@ConditionalOnMissingBean` 机制注册，允许业务方完全覆盖。

#### 4.14.1 通知渠道默认实现（NotifyChannel）

提供三种开箱即用的通知方式，均支持同步/异步发送、内置重试机制：


| 实现类                  | 渠道标识 | 激活条件                                                    | 说明                               |
| ----------------------- | -------- | ----------------------------------------------------------- | ---------------------------------- |
| `SmsNotifyChannel`      | sms      | `believe.spi.notify.sms.api-url` 配置                       | 通用短信网关接入，支持模板参数替换 |
| `EmailNotifyChannel`    | email    | `JavaMailSender` Bean存在 + `believe.spi.notify.email.from` | 基于Spring Mail，支持HTML/纯文本   |
| `DingTalkNotifyChannel` | dingtalk | `believe.spi.notify.dingtalk.webhook-url`                   | 钉钉机器人Webhook，支持@指定手机号 |

**统一模型**：`NotifyRequest`（含渠道类型、接收人、模板ID、参数、内容、重试次数）和 `NotifyResult`（成功标识、消息ID、错误码）。

#### 4.14.2 分布式ID生成器默认实现（IdGenerator）

提供两种业界主流算法实现，自动根据配置切换：


| 实现类                   | 算法         | 特点                                          | 激活条件                                     |
| ------------------------ | ------------ | --------------------------------------------- | -------------------------------------------- |
| `SnowflakeIdGenerator`   | 雪花算法     | 64位Long型、趋势递增、百万级QPS、依赖机器时钟 | 默认启用（`@ConditionalOnMissingBean`）      |
| `LeafSegmentIdGenerator` | 美团Leaf号段 | 号段模式、依赖DB、无时钟回拨问题、批量取号    | `DataSource` + `believe.spi.id.leaf.biz-tag` |

**切换逻辑**：若配置了Leaf参数则优先使用Leaf，否则使用雪花算法作为兜底。Leaf首次启动自动创建 `leaf_alloc` 表并初始化号段。

#### 4.14.3 数据序列化器默认实现（DataSerializer）

提供两种序列化格式，支持按业务场景切换：


| 实现类                   | 格式     | 特点                                                | 激活条件                  |
| ------------------------ | -------- | --------------------------------------------------- | ------------------------- |
| `JsonDataSerializer`     | JSON     | 可读性强、跨语言、基于Jackson 3                     | 默认启用                  |
| `ProtobufDataSerializer` | Protobuf | 体积小（约为JSON 1/3~1/5）、速度快（2~3倍）、强类型 | `MessageLite` 在classpath |

**设计要点**：`JsonDataSerializer` 复用 `JsonUtil.mapper()` 单例；`ProtobufDataSerializer` 内置Builder缓存，避免反射性能损耗；通过 `getContentType()` 返回标准MIME类型。

#### 4.14.4 配置规范

统一前缀：`believe.spi`


| 配置项                        | 说明                       | 示例                                                    |
| ----------------------------- | -------------------------- | ------------------------------------------------------- |
| `notify.sms.api-url`          | 短信网关地址               | `https://sms.example.com/send`                          |
| `notify.email.from`           | 发件人地址                 | `noreply@believe.com`                                   |
| `notify.dingtalk.webhook-url` | 钉钉机器人地址             | `https://oapi.dingtalk.com/robot/send?access_token=xxx` |
| `id.snowflake.worker-id`      | 雪花算法工作节点ID（0-31） | `1`                                                     |
| `id.snowflake.datacenter-id`  | 雪花算法数据中心ID（0-31） | `1`                                                     |
| `id.leaf.biz-tag`             | Leaf号段业务标识           | `order_id`                                              |
| `id.leaf.step`                | Leaf号段步长（默认2000）   | `1000`                                                  |

#### 4.14.5 依赖引入


| 依赖                       | Scope    | 说明                                         |
| -------------------------- | -------- | -------------------------------------------- |
| `believe-common-spi`       | 默认     | SPI接口定义                                  |

### 10.1 v3.0 新增内容

**新增模块：believe-common-spi-extension**

为 SPI 扩展点提供生产级默认实现，实现接口与实现分离：

### 10.5 believe-common-data 数据源模式对比


| 模式     | 配置前缀                                                                            | 适用场景           |
| -------- | ----------------------------------------------------------------------------------- | ------------------ |
| 单数据源 | `spring.datasource`（默认）                                                         | 单体应用、开发环境 |
| 读写分离 | `spring.datasource.master` / `spring.datasource.slave`                              | 读多写少，主从架构 |
| 多数据源 | `spring.datasource.master` / `spring.datasource.slave` / `spring.datasource.report` | 多库独立业务       |
| 分库分表 | `believe.data.sharding.enabled=true`                                                | 大数据量，水平拆分 |

所有模式互斥，通过 `@ConditionalOnProperty` 自动装配，单数据源为默认兜底。

### 10.6 believe-common-mq 消息队列模式对比


| 模式     | 配置值             | 依赖                           | 适用场景                       |
| -------- | ------------------ | ------------------------------ | ------------------------------ |
| RocketMQ | `ROCKETMQ`（默认） | `rocketmq-spring-boot-starter` | 事务消息、顺序消息、阿里云生态 |
| RabbitMQ | `RABBITMQ`         | `spring-boot-starter-amqp`     | 灵活路由、确认机制成熟         |
| Kafka    | `KAFKA`            | `spring-kafka`                 | 高吞吐、日志流处理             |

三种模式通过 `believe.mq.type` 属性切换，结合 `@ConditionalOnClass` + `@ConditionalOnProperty` 双重条件保证安全激活。

### 10.8 关键变更提醒

**Spring Boot 4.0 核心变更**：

1. **Servlet API 升级**：已升级到 **Servlet 6.1**，包路径为 `jakarta.servlet.*`（不是 `javax.servlet.*`）
2. **Jackson 3 迁移**：Spring Boot 4.0 默认使用 Jackson 3，核心包名变更为 `tools.jackson.*`
3. **AOP Starter 不存在独立版本**：`spring-boot-starter-aop:4.0.6` 在仓库中不存在，应直接引入 `spring-aop` 和 `aspectjweaver`
4. **Jackson 3 日期配置**：必须使用 `DateTimeFeature.WRITE_DATES_AS_TIMESTAMPS` 而非 `SerializationFeature`
5. **JDK 25 注解处理**：默认禁用，必须在 `maven-compiler-plugin` 中显式配置 `annotationProcessorPaths`
