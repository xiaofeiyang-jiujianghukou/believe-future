## 一、文档概述

### 1.1 项目定位

从零构建的通用型微服务架构，提供生产级基础设施、标准化开发规范和完整CI/CD交付流程。

### 1.2 核心目标

- 构建可复用的基础框架Starter集合
- 实现服务注册发现、配置管理、网关路由、限流熔断、认证授权等核心能力
- 建立完整的容器化部署和CI/CD流水线
- 深度掌握SPI、Spring Boot自动配置等底层机制

### 1.3 技术原则


| 原则         | 说明                                    |
| ------------ | --------------------------------------- |
| 约定优于配置 | 提供合理的默认值，降低使用门槛          |
| 开闭原则     | 通过SPI和条件注解支持扩展，核心逻辑封闭 |
| 可观测性优先 | 所有组件必须暴露日志、指标、链路信息    |
| 云原生友好   | 支持容器化部署和K8s编排                 |

## 四、核心组件设计

### 4.1 believe-common-core

**职责**：提供最基础的工具能力和公共契约。

**核心能力**：

- `Result<T>`、`PageResult<T>` 统一返回格式：`{code, message, data, timestamp}`
- `AuthContext`（ThreadLocal）和 `RequestContext`（ThreadLocal）上下文持有
- 异常体系：`BelieveException`、`BizException`
- 工具类：`JsonUtil`（Jackson 3）、`DateUtil`、`IdUtil`
- 错误码规范：1xxx参数错误，2xxx业务错误，3xxx系统错误，4xxx权限错误，5xxx服务调用错误

### 4.2 believe-common-redis

**职责**：Redis操作封装。

**暴露Bean**：

- `RedisTemplate<String, Object>`（Jackson 3序列化）
- `RedisDistributedLock`（基于SET NX EX + Lua）
- `CacheManager`（Spring Cache集成，默认TTL 1小时）

### 4.3 believe-common-data

**职责**：数据持久化增强，四种数据源模式互斥激活。


| 模式     | 激活条件                                     | 说明     |
| -------- | -------------------------------------------- | -------- |
| 单数据源 | 默认                                         | 开发环境 |
| 读写分离 | `believe.data.read-write-split.enabled=true` | 主从架构 |
| 多数据源 | `believe.data.multi-datasource.enabled=true` | 多库独立 |
| 分库分表 | `believe.data.sharding.enabled=true`         | 水平拆分 |

**其他能力**：

- `@DataSource` 注解 + AOP动态切换数据源
- MyBatis-Plus分页插件、乐观锁插件
- 自动填充：`createTime`、`updateTime`、`createBy`、`updateBy`、逻辑删除
- `BaseEntity` 抽象基类
- `CustomSqlInjector` 批量插入支持

### 4.4 believe-common-spi

**职责**：SPI扩展点接口定义。


| 扩展接口         | 方法                        | 说明         |
| ---------------- | --------------------------- | ------------ |
| `NotifyChannel`  | `send` / `sendAsync`        | 通知渠道     |
| `IdGenerator`    | `nextId` / `nextIdStr`      | 分布式ID生成 |
| `DataSerializer` | `serialize` / `deserialize` | 数据序列化   |

**加载机制**：Java原生 `ServiceLoader` + Spring `@ConditionalOnMissingBean`。

### 4.5 believe-common-spi-extension

**职责**：为上述扩展点提供生产级默认实现。

#### 通知渠道


| 实现                    | 激活条件                                           | 说明       |
| ----------------------- | -------------------------------------------------- | ---------- |
| `SmsNotifyChannel`      | `believe.spi.notify.sms.api-url`                   | 短信网关   |
| `EmailNotifyChannel`    | `JavaMailSender` + `believe.spi.notify.email.from` | 邮件发送   |
| `DingTalkNotifyChannel` | `believe.spi.notify.dingtalk.webhook-url`          | 钉钉机器人 |

#### 分布式ID生成器


| 实现                     | 算法         | 激活条件                                     |
| ------------------------ | ------------ | -------------------------------------------- |
| `SnowflakeIdGenerator`   | 雪花算法     | 默认启用                                     |
| `LeafSegmentIdGenerator` | 美团Leaf号段 | `DataSource` + `believe.spi.id.leaf.biz-tag` |

#### 序列化器


| 实现                     | 格式              | 激活条件                  |
| ------------------------ | ----------------- | ------------------------- |
| `JsonDataSerializer`     | JSON（Jackson 3） | 默认启用                  |
| `ProtobufDataSerializer` | Protobuf          | `MessageLite` 在classpath |

**覆盖机制**：所有Bean均通过 `@ConditionalOnMissingBean` 注册，业务方可自定义替换。

**配置前缀**：`believe.spi`


| 配置项                        | 示例                                                    |
| ----------------------------- | ------------------------------------------------------- |
| `notify.sms.api-url`          | `https://sms.example.com/send`                          |
| `notify.email.from`           | `noreply@believe.com`                                   |
| `notify.dingtalk.webhook-url` | `https://oapi.dingtalk.com/robot/send?access_token=xxx` |
| `id.snowflake.worker-id`      | `1`                                                     |
| `id.snowflake.datacenter-id`  | `1`                                                     |
| `id.leaf.biz-tag`             | `order_id`                                              |
| `id.leaf.step`                | `2000`                                                  |

### 4.6 believe-common-exception

**职责**：全局异常统一处理，错误码→HTTP状态码映射。

- `BelieveException` → 按错误码分类（1xxx/2xxx→400，3xxx→500，4xxx→401/403，5xxx→502）
- 参数校验异常 → 400
- 404 → 404
- 兜底 → 500

### 4.7 believe-common-log

**职责**：日志链路追踪与AOP方法日志。

- `@Log` 注解：记录入参、耗时、异常
- `TraceIdFilter`（Servlet栈，仅当 `OncePerRequestFilter` 在classpath时激活）
- `spring-boot-starter-web` 依赖声明为 `provided`，不向WebFlux项目传递

### 4.8 believe-common-feign

**职责**：Feign远程调用增强。

- `FeignRequestInterceptor`：自动注入 `X-Trace-Id`、`X-User-Id`、`X-Username`、`Authorization`

### 4.9 believe-common-swagger

**职责**：Knife4j API文档自动配置。

### 4.10 believe-common-mq

**职责**：消息队列统一封装，支持RocketMQ/RabbitMQ/Kafka三选一，通过 `believe.mq.type` 切换。

### 4.11 believe-common-security

**职责**：`AesUtil`（AES 256位 GCM加解密）。

### 4.12 believe-gateway（已实现）

**职责**：统一流量入口，基于 Spring Cloud Gateway 5.0 WebFlux 响应式架构，集成服务发现、认证鉴权、限流、灰度与链路追踪。支持 Nacos 配置动态刷新。

**过滤器链**（按 Order 顺序执行）：


| Order | 过滤器                    | 职责                                                                                                                 |
| ----- | ------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| -2    | `AuthGlobalFilter`        | 解析 JWT，白名单（`/auth/**`、`/actuator/**`）放行，其余请求调用 Sa-Token 校验登录状态，通过后向下游传递 `X-User-Id` |
| -1    | `TraceIdGlobalFilter`     | 提取或生成`X-Trace-Id`，写入 MDC 并传递至下游服务                                                                    |
| 0     | `RateLimitGlobalFilter`   | 基于滑动窗口算法实现 QPS 限流（可配置），超限返回 HTTP 429                                                           |
| 1     | `GrayReleaseGlobalFilter` | 检测`X-Gray-Release` 请求头，标记灰度版本，用于灰度路由                                                              |
| 5     | `RequestLogGlobalFilter`  | 记录请求摘要日志，格式：`[traceId] METHOD path status duration`                                                      |

**路由规范**：

- 标准路由：`/api/{service-name}/**` → `lb://{service-name}`，自动去除 `/api` 前缀
- 白名单路径：`/auth/**`、`/actuator/**` 绕过认证

**认证失败响应**：返回统一 JSON 格式，错误码 4001，消息"未登录或 Token 已过期"。

**限流实现**：策略模式，默认内置滑动窗口，可选 Sentinel。通过 `believe.gateway.rate-limit.type` 切换。

**动态配置**：`AuthGlobalFilter` 标注 `@RefreshScope`，白名单变更自动重建 Bean；`RateLimitProperties` 使用 `@ConfigurationProperties` + `@RefreshScope`，QPS 和开关变更即刻生效，无需重启。

**主要配置**：

- `believe.gateway.rate-limit.enabled`：是否启用限流（默认 false）
- `believe.gateway.rate-limit.qps`：每秒允许请求数（默认 100）
- `believe.gateway.rate-limit.type`：限流策略（sliding-window / sentinel）
- `believe.gateway.auth.whitelist`：追加白名单路径

### 4.13 believe-auth（已实现）

**职责**：认证授权中心，提供用户登录、Token 颁发、Token 校验及 RBAC 权限数据管理。

**数据模型**：经典 5 表 RBAC 结构

- `sys_user`：用户表（username, password(salt:hash), status）
- `sys_role`：角色表（name, code）
- `sys_permission`：权限表（name, code, type：菜单/按钮/API）
- `sys_user_role`：用户-角色关联表
- `sys_role_permission`：角色-权限关联表

**核心 API**：


| 方法 | 路径              | 说明                                   | 认证 |
| ---- | ----------------- | -------------------------------------- | ---- |
| POST | `/auth/login`     | 用户名密码登录，返回 JWT（RS256 签名） | 否   |
| POST | `/auth/register`  | 新用户注册                             | 否   |
| POST | `/auth/logout`    | 登出（Token 黑名单）                   | 是   |
| GET  | `/auth/user-info` | 获取当前用户信息及角色、权限列表       | 是   |

**与网关协作**：`believe-gateway` 的 `AuthGlobalFilter` 调用 `StpUtil.checkLogin()` 完成认证，网关不重复执行权限查询；权限数据通过 `StpInterfaceImpl` 从数据库加载，供下游服务使用。

**密码安全**：采用 BCrypt 加密存储。

**JWT 密钥**：使用非对称加密（RS256），私钥仅 auth 服务持有，公钥供网关校验。

### 4.14 believe-user（已实现）

**职责**：用户中心服务，提供用户个人资料管理、管理员分页查询及用户信息维护接口。依赖 `believe-auth` 提供的认证与权限数据。

**核心 API**：


| 方法   | 路径         | 说明                                     | 权限要求      |
| ------ | ------------ | ---------------------------------------- | ------------- |
| GET    | `/user/info` | 获取当前登录用户信息                     | 登录即可      |
| PUT    | `/user/info` | 更新当前用户资料（昵称、邮箱、手机号等） | 登录即可      |
| GET    | `/user/{id}` | 查询指定用户详情                         | `user:manage` |
| GET    | `/user/list` | 分页查询用户列表（支持关键词）           | `user:manage` |
| DELETE | `/user/{id}` | 删除用户                                 | `user:manage` |

**权限控制**：使用 Sa-Token 注解 `@SaCheckPermission("user:manage")` 声明权限要求。权限数据由 `believe-auth` 模块通过 `StpInterface` 提供，`believe-user` 无需重复查询数据库。

**数据层**：基于 `believe-common-data` 模块，使用 MyBatis-Plus 访问用户表（`sys_user`），字段映射符合 `BaseEntity` 规范（自动填充创建时间、更新时间等）。

**与网关协作**：网关认证通过后，将 `X-User-Id` 传递给 `believe-user`，服务通过 `RequestContext` 获取当前用户 ID，实现"只能修改本人资料"的业务规则。

### 4.15 believe-job（已实现）

**职责**：xxl-job 执行器自动配置模块，引入即自动注册执行器，并提供任务级链路追踪能力。

**自动配置**：根据 `believe.job.enabled` 条件创建 `XxlJobSpringExecutor` 并注册到调度中心。只需配置调度中心地址、执行器名称、端口等即可使用，无需额外 Java 配置。

**链路追踪**：提供 `JobTraceHelper` 工具类，在任务方法入口调用 `initTrace(taskName)` 生成 TraceId 并写入 `RequestContext` 和 MDC，任务结束时调用 `clearTrace()`。该 TraceId 会通过 `believe-common-feign` 自动传递到下游服务，实现全链路串联。

**核心配置**（`believe.job.*`）：


| 配置项               | 默认值                              | 说明             |
| -------------------- | ----------------------------------- | ---------------- |
| `enabled`            | true                                | 是否启用执行器   |
| `admin-addresses`    | http://127.0.0.1:8080/xxl-job-admin | 调度中心地址     |
| `app-name`           | believe-job-executor                | 执行器应用名     |
| `access-token`       | default_token                       | 通信令牌         |
| `port`               | 9999                                | 执行器监听端口   |
| `log-path`           | /data/applogs/xxl-job/jobhandler    | 任务日志存储路径 |
| `log-retention-days` | 30                                  | 日志保留天数     |

**关闭方式**：设置 `believe.job.enabled=false` 即可，适用于本地开发环境。

## 五、Docker容器化方案

### 5.1 镜像策略

基础镜像统一托管在阿里云ACR（`crpi-27zlqugq2208c0pz.cn-hangzhou.personal.cr.aliyuncs.com`），含 4 个预置镜像：


| 镜像              | 用途                      |
| ----------------- | ------------------------- |
| MySQL 8.0         | 业务数据库                |
| Redis 7-alpine    | 缓存与分布式锁            |
| Nacos Serverv2.5.1 | 注册发现与配置管理        |
| Maven 3.9 + JDK25 | 多模块构建                |
| Eclipse Temurin JRE 25-alpine | 运行时镜像      |

### 5.2 多阶段构建（Dockerfile）

单个 `Dockerfile` 支持所有业务服务的构建，通过 `SERVICE_DIR` ARG 参数区分目标模块：

- **阶段一**：Maven 编译 —— 先 `mvn install` 安装 `believe-framework` 到本地仓库，再 `mvn package` 目标服务
- **阶段二**：运行时 —— JRE Alpine 镜像，仅包含 repackaged fat JAR，JVM 默认 `-Xmx256m`

### 5.3 Docker Compose 编排

`docker-compose.yml` 定义 7 个服务，按依赖顺序启动：

```
mysql ─────────────┐
redis              │
nacos ── nacos-init ── gateway
                   ├── auth
                   └── user
```

**基础设施层**：


| 服务       | 容器名             | 端口映射        | 说明                           |
| ---------- | ------------------ | --------------- | ------------------------------ |
| mysql      | believe-mysql      | 13306→3306      | 挂载 `init-db.sql` 自动建表    |
| redis      | believe-redis      | 16379→6379      | AOF 持久化                     |
| nacos      | believe-nacos      | 18848→8848, 19848→9848 | standalone 模式，关闭认证 |
| nacos-init | believe-nacos-init | —               | Nacos 就绪后创建 dev 命名空间、发布 `common-redis.yaml` |

**业务服务层**：


| 服务    | 容器名          | 端口映射          | Profile | 附加环境变量                          |
| ------- | --------------- | ----------------- | ------- | ------------------------------------- |
| gateway | believe-gateway | 18080→8080, 18081→8081 | pro     | —                                     |
| auth    | believe-auth    | 18101→8101, 18102→8102 | pro     | MYSQL_HOST, MYSQL_USER, MYSQL_PASSWORD, JWT_SECRET |
| user    | believe-user    | 18201→8201, 18202→8202 | pro     | MYSQL_HOST, MYSQL_USER, MYSQL_PASSWORD |

**启动命令**：`docker compose up -d`

### 5.4 Nacos 初始化

`nacos-init` 容器在 Nacos 健康检查通过后自动执行：

1. 创建 `dev` 命名空间（ID = dev）
2. 发布共享配置 `common-redis.yaml`（Redis 地址指向容器名 `redis:6379`）

业务服务通过 `spring.config.import` 导入 Nacos 配置，`shared-configs` 引用共享配置并开启自动刷新。


## 七、配置规范

### 7.1 配置文件层级

`application.yml` → `application-{env}.yml` → Nacos配置中心（最高优先级，支持动态刷新）

> Spring Cloud 2025.x 已移除 bootstrap 上下文，改用 `spring.config.import` 显式导入 Nacos 配置源。

### 7.2 环境配置分离


| 文件                  | 用途                                             |
| --------------------- | ------------------------------------------------ |
| `application.yml`     | 公共配置（端口、datasource、mybatis-plus、sa-token、日志） |
| `application-dev.yml` | 本地开发（Nacos 指向 `localhost:18848`）         |
| `application-pro.yml` | Docker 部署（Nacos 指向容器名 `nacos:8848`）     |

### 7.3 Nacos规划


| Namespace | 用途     | 配置集示例                                    |
| --------- | -------- | --------------------------------------------- |
| dev       | 开发环境 | `believe-auth.yaml`、`believe-user.yaml`       |
| test      | 测试环境 | `user-service-test.yaml`                      |
| prod      | 生产环境 | `user-service-prod.yaml`                      |
| common    | 公共配置 | `common-redis.yaml`、`common-datasource.yaml`  |

**动态刷新**：所有通过 `@ConfigurationProperties` + `@RefreshScope` 绑定的配置项（限流 QPS、白名单等），Nacos 推送后自动刷新，无需重启。

## 十一、关键版本说明

### v3.3 相对于 v3.2 的核心变化

1. **Docker Compose 多服务编排实现**

   - 完成 `docker-compose.yml`，定义 MySQL、Redis、Nacos 3 个基础设施 + gateway、auth、user 3 个业务服务，共 7 个容器
   - 新增 `nacos-init` 容器，自动创建 dev 命名空间并发布共享配置
   - 依赖链与健康检查完整配置，`docker compose up -d` 一键启动全部服务
   - 服务间通过容器名互联（Nacos 地址 `nacos:8848`，MySQL 地址 `mysql:3306`，Redis 地址 `redis:6379`）

2. **统一多阶段 Docker 构建**

   - 单个 `Dockerfile` 通过 `SERVICE_DIR` ARG 支持 gateway/auth/user 三个服务的构建
   - 构建阶段：先安装 `believe-framework`，再打包目标服务；运行阶段：JRE Alpine 镜像
   - 各服务独立 `Dockerfile` 统一指向根目录 `Dockerfile`

3. **Nacos 注册发现与配置中心联调成功**

   - 三个业务服务均成功注册到 Nacos dev 命名空间
   - `shared-configs` 机制加载 `common-redis.yaml`，Redis 地址指向容器名
   - 配置动态刷新功能验证通过：修改 Nacos 中的 QPS 和白名单配置，无需重启网关即可生效

4. **believe-gateway 本地启动修复**

   - Spring Boot 4.x 将 `WebServerInitializedEvent` 从 `spring-boot` jar 拆分至 `spring-boot-web-server` jar
   - `spring-cloud-gateway-server-webflux:5.0.0` 将 `spring-boot-starter-webflux` 声明为 optional，不传递
   - 解决方案：显式引入 `spring-boot-starter-webflux` 依赖

5. **believe-common-log 依赖优化**

   - `spring-boot-starter-web` 从 compile 改为 provided，不向 WebFlux 项目传递 Servlet/MVC 栈
   - `LogAutoConfiguration` 中 `TraceIdFilter` 加 `@ConditionalOnClass(OncePerRequestFilter.class)`，WebFlux 环境自动跳过
   - gateway pom.xml 删除对应的 exclusion，配置更干净

6. **网关配置动态刷新**

   - 新增 `RateLimitProperties`（`@ConfigurationProperties` + `@RefreshScope`），绑定 `believe.gateway.rate-limit.*` 配置
   - `SlidingWindowRateLimiter` 和 `SentinelRateLimiter` 改为每次请求实时读取配置值，不再缓存为 final 字段
   - `SentinelRateLimiter` 监听 `RefreshScopeRefreshedEvent`，配置变更时自动更新 FlowRule
   - `AuthGlobalFilter` 加 `@RefreshScope`，白名单变更自动重建 Bean

7. **配置体系升级**

   - 移除 bootstrap.yml，改用 `application-{profile}.yml` 分层 + `spring.config.import`
   - 本地开发（dev profile）Nacos 指向 `localhost:18848`，Docker（pro profile）Nacos 指向 `nacos:8848`
   - Docker Compose 通过 `SPRING_PROFILES_ACTIVE=pro` 激活部署配置

### Spring Boot 4.0 重要提醒

1. Servlet API 升级为 `jakarta.servlet.*`（Servlet 6.1）
2. Jackson 3 核心包名变更为 `tools.jackson.*`，使用 `JsonMapper.builder()`
3. 无独立 `spring-boot-starter-aop`，需直接引入 `spring-aop` 和 `aspectjweaver`
4. 日期配置使用 `DateTimeFeature.WRITE_DATES_AS_TIMESTAMPS`
5. `WebServerInitializedEvent` 位于 `spring-boot-web-server` 模块，`spring-cloud-gateway-server-webflux` 不传递 `spring-boot-starter-webflux`
