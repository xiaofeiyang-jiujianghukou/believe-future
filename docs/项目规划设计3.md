## 二、五大核心技术深潜

### 1. SPI - 实现极致的可扩展架构

SPI是Java生态中最被低估的能力，Dubbo、Spring、JDBC都大量使用。它让你的架构具备"插拔式"扩展能力。

**核心机制**：接口定义在规范层，具体实现在业务层，通过 `META-INF/services/` 自动发现。

**实战场景**：假设你的通用通知模块支持多种发送渠道，使用SPI后新增短信渠道只需添加依赖，无需修改核心代码。

```
believe-common-notify/               # 规范层
├── src/main/java/com/believe/notify/
│   └── NotifyChannel.java           # 接口定义
└── src/main/resources/
    └── META-INF/services/
        └── com.believe.notify.NotifyChannel  # 无（规范层不实现）

believe-notify-email/                # 实现层1
├── pom.xml (依赖common-notify)
└── src/main/resources/META-INF/services/
    └── com.believe.notify.NotifyChannel
        └── com.believe.notify.email.EmailChannel  # 一行：实现类全限定名

believe-notify-sms/                  # 实现层2
└── src/main/resources/META-INF/services/
    └── com.believe.notify.NotifyChannel
        └── com.believe.notify.sms.SmsChannel
```

**核心代码**：
```java
// 1. 定义SPI接口
package com.believe.common.spi;
public interface DataSerializer {
    byte[] serialize(Object obj);
    Object deserialize(byte[] data);
}

// 2. 提供默认实现
package com.believe.common.spi.impl;
public class JsonSerializer implements DataSerializer { ... }

// 3. 使用ServiceLoader加载
public class SerializerFactory {
    private static final ServiceLoader<DataSerializer> LOADER =
        ServiceLoader.load(DataSerializer.class);

    public static DataSerializer getSerializer(String name) {
        for (DataSerializer serializer : LOADER) {
            if (serializer.supports(name)) return serializer;
        }
        // 降级到默认实现
        return new JsonSerializer();
    }
}
```

**SPI vs Spring自动配置**：SPI是Java原生扩展机制，Spring自动配置是Spring Boot特有的。两者配合使用——SPI定义扩展点，Spring Boot Starter自动装配SPI的实现。

### 2. Spring Boot Starter自动配置 - 开箱即用的基础设施

理解自动配置是掌握Spring Boot精髓的关键。从`@SpringBootApplication`到`@EnableAutoConfiguration`，再到`spring.factories`，这个链路要彻底搞清楚。

**核心原理**：
1. `@SpringBootApplication` 包含 `@EnableAutoConfiguration`
2. `@EnableAutoConfiguration` 通过 `@Import(AutoConfigurationImportSelector.class)` 导入
3. `AutoConfigurationImportSelector` 从 `META-INF/spring.factories` 读取配置类
4. 条件注解（`@ConditionalOnClass`、`@ConditionalOnMissingBean`等）决定是否生效

**实战：构建 believe-common-redis-starter**

```java
// 1. 配置属性类
@ConfigurationProperties(prefix = "believe.redis")
public class BelieveRedisProperties {
    private String host = "localhost";
    private int port = 6379;
    private int database = 0;
    private JedisPool pool = new JedisPool();

    @Data
    public static class JedisPool {
        private int maxActive = 8;
        private int maxIdle = 8;
        private int minIdle = 0;
    }
}

// 2. 核心自动配置类
@Configuration
@ConditionalOnClass(RedisTemplate.class)
@EnableConfigurationProperties(BelieveRedisProperties.class)
public class BelieveRedisAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public RedisTemplate<String, Object> redisTemplate(
            RedisConnectionFactory factory,
            BelieveRedisProperties properties) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);

        // 使用Jackson序列化
        Jackson2JsonRedisSerializer<Object> jackson =
            new Jackson2JsonRedisSerializer<>(Object.class);
        template.setDefaultSerializer(jackson);
        return template;
    }

    @Bean
    @ConditionalOnMissingBean
    public RedisDistributedLock redisDistributedLock(
            RedisTemplate<String, Object> redisTemplate) {
        return new RedisDistributedLock(redisTemplate);
    }
}

// 3. 提供增强功能：分布式锁
public class RedisDistributedLock {
    private final RedisTemplate<String, Object> redisTemplate;

    public boolean tryLock(String key, String value, long expireTime, TimeUnit unit) {
        Boolean result = redisTemplate.opsForValue()
            .setIfAbsent(key, value, expireTime, unit);
        return Boolean.TRUE.equals(result);
    }

    public void unlock(String key, String value) {
        String script = "if redis.call('get', KEYS[1]) == ARGV[1] then " +
                        "return redis.call('del', KEYS[1]) else return 0 end";
        redisTemplate.execute(new DefaultRedisScript<>(script, Long.class),
            Collections.singletonList(key), value);
    }
}

// 4. META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
com.believe.redis.BelieveRedisAutoConfiguration

// 5. 使用者配置
// pom.xml 引入依赖
// application.yml
believe:
  redis:
    host: redis.svc.cluster.local
    port: 6379
    pool:
      max-active: 20

// 业务代码直接注入
@Autowired
private RedisDistributedLock distributedLock;
```

**条件注解清单**：
| 注解 | 作用 |
|------|------|
| `@ConditionalOnClass` | classpath存在指定类时生效 |
| `@ConditionalOnMissingClass` | classpath不存在指定类时生效 |
| `@ConditionalOnBean` | 容器存在指定Bean时生效 |
| `@ConditionalOnMissingBean` | 容器不存在指定Bean时生效（支持覆盖默认实现） |
| `@ConditionalOnProperty` | 配置项满足条件时生效 |
| `@ConditionalOnWebApplication` | Web应用环境下生效 |
| `@AutoConfigureBefore/After` | 控制多个配置类的加载顺序 |

### 3. 网关深度定制 - 掌握请求的完整生命周期

网关是所有流量的咽喉，对网关的深度定制能力直接影响整个架构的灵活性。

**网关过滤器链执行流程**：
```
客户端请求
    ↓
GlobalFilter (最高优先级，所有路由都执行)
    ├── LoggingGlobalFilter (日志记录，生成TraceId)
    ├── AuthGlobalFilter (JWT解析，用户上下文注入)
    ├── RateLimitGlobalFilter (限流检测)
    └── GrayReleaseGlobalFilter (灰度路由决策)
    ↓
路由匹配 (RoutePredicate)
    ↓
GatewayFilter (特定路由的过滤器)
    ↓
代理请求到下游服务
    ↓
响应返回 (Response Filter，后置处理)
```

**核心代码实现**：

```java
// 1. 日志追踪过滤器 - 生成全局TraceId
@Component
@Order(-1)
public class TraceIdGlobalFilter implements GlobalFilter {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String traceId = exchange.getRequest().getHeaders()
            .getFirst("X-Trace-Id");
        if (StringUtils.isEmpty(traceId)) {
            traceId = UUID.randomUUID().toString().replace("-", "");
        }
        // 存入MDC，方便日志输出
        MDC.put("traceId", traceId);

        // 向下游服务传递
        ServerWebExchange mutatedExchange = exchange.mutate()
            .request(builder -> builder.header("X-Trace-Id", traceId))
            .build();

        return chain.filter(mutatedExchange)
            .doFinally(signalType -> MDC.clear());
    }
}

// 2. 认证过滤器 - JWT解析并注入用户上下文
@Component
@Order(-2)
public class AuthGlobalFilter implements GlobalFilter {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String token = extractToken(exchange.getRequest());

        if (StringUtils.isEmpty(token)) {
            // 白名单路径放过
            if (isWhiteList(exchange.getRequest())) {
                return chain.filter(exchange);
            }
            return unauthorized(exchange, "Missing token");
        }

        try {
            // JWT解析
            Claims claims = JwtUtil.parseToken(token);
            String userId = claims.getSubject();
            String username = claims.get("username", String.class);
            Set<String> authorities = claims.get("authorities", Set.class);

            // 创建认证上下文
            AuthContext authContext = new AuthContext(userId, username, authorities);

            // 存入ReactiveRequestContextHolder（下游服务可获取）
            ServerWebExchange mutated = exchange.mutate()
                .request(r -> r.header("X-User-Id", userId)
                               .header("X-Username", username)
                               .header("X-Authorities", JSON.toJSONString(authorities)))
                .build();

            return ReactiveRequestContextHolder.setContext(mutated, authContext)
                .then(chain.filter(mutated));
        } catch (Exception e) {
            return unauthorized(exchange, "Invalid token");
        }
    }

    private boolean isWhiteList(ServerHttpRequest request) {
        return request.getURI().getPath().matches("/auth/login|/auth/register|/actuator/.*");
    }
}

// 3. 限流过滤器 - 使用Sentinel
@Component
public class RateLimitGlobalFilter implements GlobalFilter {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String resource = exchange.getRequest().getPath().value();
        String userId = exchange.getRequest().getHeaders().getFirst("X-User-Id");

        // 基于用户ID的限流
        String key = userId != null ? resource + ":" + userId : resource;

        try {
            // Sentinel限流判断
            Entry entry = SphU.entry(key, EntryType.IN);
            return chain.filter(exchange)
                .doFinally(signalType -> entry.exit());
        } catch (BlockException e) {
            return handleLimitExceeded(exchange);
        }
    }
}

// 4. 灰度发布过滤器
@Component
public class GrayReleaseGlobalFilter implements GlobalFilter {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        HttpRequest request = exchange.getRequest();

        // 灰度策略1: 基于Header
        String version = request.getHeaders().getFirst("X-Version");
        if ("gray".equals(version)) {
            exchange = exchange.mutate()
                .request(r -> r.header("X-Gray", "true"))
                .build();
        }

        // 灰度策略2: 基于用户ID尾号
        String userId = request.getHeaders().getFirst("X-User-Id");
        if (userId != null && userId.endsWith("5")) {
            exchange = exchange.mutate()
                .request(r -> r.header("X-Gray", "true"))
                .build();
        }

        // 灰度策略3: 基于用户IP白名单
        String clientIp = request.getRemoteAddress().getAddress().getHostAddress();
        if (grayIpSet.contains(clientIp)) {
            exchange = exchange.mutate()
                .request(r -> r.header("X-Gray", "true"))
                .build();
        }

        return chain.filter(exchange);
    }
}
```

### 4. RBAC - 从用户到权限的完整链路

RBAC（Role-Based Access Control）是企业级系统的核心权限模型。不仅要会用框架，更要理解底层原理。

**数据模型（5张核心表）**：
```sql
-- 用户表
CREATE TABLE `user` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `username` VARCHAR(50) NOT NULL UNIQUE,
    `password` VARCHAR(255) NOT NULL,
    `status` TINYINT DEFAULT 1,  -- 1启用 0禁用
    `create_time` DATETIME
);

-- 角色表
CREATE TABLE `role` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `role_code` VARCHAR(50) NOT NULL UNIQUE,  -- ADMIN, USER, MANAGER
    `role_name` VARCHAR(50) NOT NULL
);

-- 权限表（资源+操作）
CREATE TABLE `permission` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `resource_code` VARCHAR(100) NOT NULL,   -- 资源：user、order、product
    `action` VARCHAR(20) NOT NULL,            -- 操作：READ、WRITE、DELETE
    `permission_code` VARCHAR(100) UNIQUE     -- 组合：user:READ
);

-- 用户角色关联表
CREATE TABLE `user_role` (
    `user_id` BIGINT,
    `role_id` BIGINT,
    PRIMARY KEY (`user_id`, `role_id`)
);

-- 角色权限关联表
CREATE TABLE `role_permission` (
    `role_id` BIGINT,
    `permission_id` BIGINT,
    PRIMARY KEY (`role_id`, `permission_id`)
);
```

**权限注解 + AOP实现**：

```java
// 1. 自定义权限注解
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequirePermission {
    String[] value();           // 所需权限，如 "user:READ"
    Logical logical() default Logical.AND;  // AND/OR关系
}

// 2. 权限校验AOP
@Aspect
@Component
public class PermissionAspect {

    @Around("@annotation(requirePermission)")
    public Object checkPermission(ProceedingJoinPoint joinPoint,
                                   RequirePermission requirePermission) throws Throwable {
        // 获取当前登录用户
        AuthContext authContext = AuthContextHolder.get();
        if (authContext == null) {
            throw new UnauthorizedException("用户未登录");
        }

        // 获取用户的权限集合（从缓存或数据库加载）
        Set<String> userPermissions = getPermissions(authContext.getUserId());

        // 权限校验
        String[] required = requirePermission.value();
        boolean hasPermission;

        if (requirePermission.logical() == Logical.AND) {
            hasPermission = Arrays.stream(required).allMatch(userPermissions::contains);
        } else {
            hasPermission = Arrays.stream(required).anyMatch(userPermissions::contains);
        }

        if (!hasPermission) {
            throw new ForbiddenException("权限不足，需要权限：" + Arrays.toString(required));
        }

        return joinPoint.proceed();
    }
}

// 3. 在Controller中使用
@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping("/{id}")
    @RequirePermission("user:READ")
    public Result<UserVO> getUser(@PathVariable Long id) {
        return Result.success(userService.getById(id));
    }

    @DeleteMapping("/{id}")
    @RequirePermission("user:DELETE")
    public Result<Void> deleteUser(@PathVariable Long id) {
        userService.deleteById(id);
        return Result.success();
    }

    @PostMapping
    @RequirePermission(value = {"user:WRITE", "user:CREATE"}, logical = Logical.OR)
    public Result<Void> createUser(@RequestBody UserCreateDTO dto) {
        return Result.success();
    }
}
```
