## 一、文档概述

### 1.1 项目定位

Believe 是一套从零构建的通用型微服务架构，旨在提供生产级的基础设施能力、标准化的开发规范和完整的CI/CD交付流程。

### 1.2 核心目标

- 构建可复用的基础框架Starter集合
- 实现服务注册发现、配置管理、网关路由、限流熔断、认证授权等核心能力
- 建立完整的容器化部署和CI/CD流水线
- 深度掌握SPI、Spring Boot自动配置等底层机制

### 1.3 技术原则


| 原则         | 说明                                    |
| ------------ | --------------------------------------- |
| 约定优于配置 | 提供合理的默认值，降低使用门槛          |
| 开闭原则     | 通过SPI和条件注解支持扩展，核心逻辑封闭 |
| 可观测性优先 | 所有组件必须暴露日志、指标、链路信息    |
| 云原生友好   | 支持容器化部署和K8s编排                 |

## 四、核心组件设计

### 4.1 believe-common-core

**职责**：提供最基础的工具能力和公共契约


| 包路径                              | 功能         | 说明                               |
| ----------------------------------- | ------------ | ---------------------------------- |
| `com.believe.common.core.result`    | 统一返回结果 | `Resultt`、`PageResultt`           |
| `com.believe.common.core.constants` | 系统常量     | 服务名、Header名、错误码           |
| `com.believe.common.core.utils`     | 通用工具类   | `JsonUtil`、`IdUtil`、`DateUtil`   |
| `com.believe.common.core.exception` | 基础异常定义 | `BelieveException`、`BizException` |
| `com.believe.common.core.context`   | 上下文持有者 | `AuthContext`、`RequestContext`    |

**核心契约定义**：

- 统一响应格式：`{ code, message, data, timestamp }`
- 错误码规范：1xxx参数错误，2xxx业务错误，3xxx系统错误，4xxx权限错误，5xxx服务调用错误
- 透传Header约定：`X-Trace-Id`、`X-User-Id`、`X-Username`、`X-Authorities`

### 4.2 believe-common-redis (Starter)

**职责**：封装Redis操作，提供开箱即用的缓存能力

**自动配置触发条件**：`RedisTemplate` 存在于classpath

**暴露的Bean**：


| Bean名称               | 类型                   | 说明              |
| ---------------------- | ---------------------- | ----------------- |
| `redisTemplate`        | `RedisTemplatestring,` | Jackson序列化配置 |
| `redisDistributedLock` | `RedisDistributedLock` | 分布式锁实现      |
| `cacheManager`         | `CacheManager`         | Spring Cache集成  |

**配置项** (`believe.redis.*`)：


| 配置项            | 默认值    | 说明             |
| ----------------- | --------- | ---------------- |
| `host`            | localhost | Redis主机地址    |
| `port`            | 6379      | Redis端口        |
| `database`        | 0         | 数据库索引       |
| `pool.max-active` | 8         | 连接池最大连接数 |
| `pool.max-idle`   | 8         | 连接池最大空闲数 |

### 4.3 believe-common-data (Starter)

**职责**：数据持久化增强，多数据源支持

**自动配置触发条件**：`DataSource` 和 `MybatisPlusAutoConfiguration` 存在

**暴露的Bean**：


| Bean名称                 | 类型                    | 说明                             |
| ------------------------ | ----------------------- | -------------------------------- |
| `mybatisPlusSqlInjector` | `ISqlInjector`          | 自定义方法注入（批量插入等）     |
| `metaObjectHandler`      | `MetaObjectHandler`     | 自动填充创建人/时间、更新人/时间 |
| `paginationInterceptor`  | `PaginationInterceptor` | 分页插件                         |

**自动填充规范**：

- `createTime`：插入时自动填充当前时间
- `updateTime`：插入和更新时自动填充当前时间
- `createBy`：从`AuthContext`获取当前用户ID
- `updateBy`：从`AuthContext`获取当前用户ID

**多数据源配置**：


| 配置项                      | 说明           |
| --------------------------- | -------------- |
| `believe.datasource.master` | 主库配置（写） |
| `believe.datasource.slave`  | 从库配置（读） |

### 4.4 believe-common-spi

**职责**：定义SPI扩展点，实现插件化架构

**SPI扩展点定义**：


| 扩展接口         | 方法                      | 说明                             |
| ---------------- | ------------------------- | -------------------------------- |
| `DataSerializer` | `serialize`/`deserialize` | 数据序列化扩展                   |
| `NotifyChannel`  | `send`                    | 通知渠道扩展（短信/邮件/站内信） |
| `IdGenerator`    | `nextId`                  | 分布式ID生成扩展                 |

**加载机制**：使用Java原生 `ServiceLoader`，配合Spring Boot `@ConditionalOnMissingBean` 实现平滑覆盖

### 4.5 believe-gateway

**职责**：统一流量入口，路由转发、认证鉴权、限流熔断

**核心过滤器链**（按Order排序）：


| Order | 过滤器名称                | 职责                      |
| ----- | ------------------------- | ------------------------- |
| -2    | `AuthGlobalFilter`        | JWT解析，用户上下文注入   |
| -1    | `TraceIdGlobalFilter`     | 生成/传递TraceId，日志MDC |
| 0     | `RateLimitGlobalFilter`   | Sentinel限流检测          |
| 1     | `GrayReleaseGlobalFilter` | 灰度路由决策              |
| 5     | `RequestLogGlobalFilter`  | 请求日志记录              |

**路由配置规范**：

- 路径前缀：`/api/{service-name}/**` 映射到对应微服务
- 白名单：`/auth/**`、`/actuator/**` 绕过认证

**限流资源配置**：

- 默认每API 100 QPS
- 按用户维度每用户每API 20 QPS

### 4.6 believe-auth（认证中心）

**职责**：用户认证、Token颁发、权限管理

**核心接口**：


| 接口路径            | 方法 | 说明                        |
| ------------------- | ---- | --------------------------- |
| `/auth/login`       | POST | 账号密码登录，返回JWT Token |
| `/auth/logout`      | POST | 登出，黑名单失效Token       |
| `/auth/refresh`     | POST | 刷新Token                   |
| `/auth/check`       | GET  | 校验Token有效性             |
| `/auth/permissions` | GET  | 获取当前用户权限列表        |

**RBAC模型**（5表结构）：


| 表名              | 说明                  |
| ----------------- | --------------------- |
| `user`            | 用户基本信息          |
| `role`            | 角色定义              |
| `permission`      | 权限定义（资源+操作） |
| `user_role`       | 用户-角色关联         |
| `role_permission` | 角色-权限关联         |

**Token设计**：

- 算法：RS256（非对称加密）
- 有效期：2小时
- Refresh Token有效期：7天
- Payload包含：`userId`, `username`, `authorities`, `exp`

### 4.7 believe-job

**职责**：xxl-job执行器封装，简化任务开发

**自动配置触发条件**：`XxlJobConfiguration` 条件判断

**暴露能力**：

- 自动注册执行器到调度中心
- 提供 `@BelieveXxlJob` 注解增强（自动记录执行日志、异常告警）

**配置项**：


| 配置项                     | 说明         |
| -------------------------- | ------------ |
| `xxl.job.admin.addresses`  | 调度中心地址 |
| `xxl.job.executor.appname` | 执行器应用名 |
| `xxl.job.executor.port`    | 执行器端口   |

## 五、CI/CD设计

### 5.1 流水线阶段

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  Build   │ -> │  Image   │ -> │  Deploy  │ -> │   Test   │ -> │  Deploy  │
```

| 环境    | 分支        | 部署方式 | 用途     |
