## 四、版本兼容性风险提示

### 1. 包路径变更 (关键)

`Spring Boot 3.x` 开始，所有 `javax.*` 包路径已迁移到 `jakarta.*`。你的项目基于 `4.0.x`，这点必须注意：

**变更示例**:

- `javax.servlet.*` → `jakarta.servlet.*`
- `javax.persistence.*` → `jakarta.persistence.*`
- `javax.validation.*` → `jakarta.validation.*`

**应对**:

- 所有代码、第三方库、你的Starter模块都必须使用`jakarta.*`命名空间
- 检查所有依赖项是否已适配Jakarta EE 10+

### 2. Spring Cloud Alibaba 版本滞后 (中高风险)

Spring Cloud Alibaba的适配通常晚于Spring Cloud官方发布2-3个月。`Spring Cloud 2025.1` 是个全新的大版本，预计需要更长的适配周期。

**应对**:

- 将架构设计为**对Alibaba组件弱依赖**，通过SPI允许替换或降级方案
- 在`dependencyManagement`中暂时不引入`spring-cloud-alibaba-dependencies` BOM
- 分别引入经过验证的Nacos、Sentinel客户端版本，并做好回归测试

### 3. MyBatis-Plus兼容性 (低风险)

MyBatis-Plus 3.5.x系列对Spring Boot 3.x支持良好，但对4.x需要验证。

**应对**:

- 关注MyBatis-Plus官方进度，必要时使用`mybatis-spring-boot-starter`官方版替代
- 在项目中抽象数据访问层接口，便于切换实现

### 4. JDK 25 新特性限制 (低风险)

虽然目标使用JDK 25，但考虑到编译兼容性，建议：

**应对**:

- `maven-compiler-plugin`配置`release=25`或`source/target=25`
- 避免使用JDK 25的预览特性（如`--enable-preview`）
- CI/CD环境需安装JDK 25并正确设置`JAVA_HOME`

## 六、执行计划建议

考虑到版本前沿性，建议分阶段推进：


| 阶段         | 时间       | 目标            | 关键产出                                                                                   |
| ------------ | ---------- | --------------- | ------------------------------------------------------------------------------------------ |
| **第一阶段** | 第1-2周    | 基础骨架搭建    | 父POM配置完成，common-core模块通过编译                                                     |
| **第二阶段** | 第3-5周    | 基础设施等待期  | 搭建Gateway/Auth模块骨架，但不集成Alibaba组件                                              |
| **第三阶段** | 第6-8周    | 替代方案验证    | 使用原生Spring Cloud LoadBalancer + OpenFeign实现服务发现和调用，验证无Alibaba组件的可行性 |
| **第四阶段** | 待官方发布 | Alibaba组件集成 | 获取官方BOM后，替换为统一版本，进行全面回归测试                                            |

这个计划可以让你站在技术最前沿的同时，规避版本不兼容的风险。如果你同意这个方案，我们可以从第一阶段开始，进入`believe-common-core`模块的具体代码结构设计了。
